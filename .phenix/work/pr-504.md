# PR 504 working state

## Current state

Base: main after #505 merge (`f16beb6e`)
Phase: implementation

## Decisions

- #503 and #505 are on main. #504 consumes their value/capability and client-tool APIs and does not recreate callback-specific transport.
- `clients/nvim` is now the canonical frontend source. Only `phenix_nvim.runtime` owns the native `phenix` client userdata.
- Keep unsent compose/UI state local. Runtime session, transcript, execution, permission, and review truth must come from Phenix.
- The first frontend slice may use the existing standard ACP session wrapper for text prompts while the missing production SDK value/observable surface is repaired. Do not encode a private application schema in Lua to bypass that gap.

## Findings

- The repaired branch removed obsolete #505 ancestry and is based directly on merged main.
- Exact-head Rust, Product, integration, and runtime lanes passed. Source failed only because the three #504 specs lacked required `status:` lifecycle metadata.
- The native Lua binding already provides `client:sdk()`, `client:application()`, standard session handles, bounded host polling, request handles, generic callable lifting, and client tool authoring.
- The application contract already carries ordered text/image/resource prompt content and typed session/execution updates.
- Production plugins currently publish no `SdkObservableResource`; observable registration exists only in tests/fixtures. The specified observable-backed transcript therefore needs a production SDK contribution before that checklist item can be complete.
- `phenix-acp-stdio` still has no configured-runtime bridge or packaged `phenix-acp` executable. A packaged Neovim end-to-end spawn cannot be accepted until that bridge exists.
- The first canonical frontend batch adds package/runtime/sidebar/compose/transcript primitives and headless behavior regressions without inventing raw ACP framing or private application schemas.

## Tried / rejected

- Reusing the standalone `phenix-nvim` transport/controller stack: rejected because it owns protocol and runtime truth that now belong to the native binding and Phenix.
- Handwriting application value schemas in Lua to reach multimodal Prompt before the SDK surface exists: rejected. Fix the runtime SDK contribution instead.
- Treating current standard ACP updates as the final transcript source: rejected. They remain a transport fallback; the target source is the value-level observable surface.
