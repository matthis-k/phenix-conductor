## Decisions

- Reuse #503 generic `CallableRef` dispatch. Do not add a client-tool-specific callback protocol.
- Admissions are ephemeral and client-generation scoped. Backends see ordinary callable and model-tool descriptors.
- The application host owns admitted-client execution: permission first, then generic callable dispatch.
- ACP handlers that can trigger nested ACP traffic must release the dispatch loop with `connection.spawn(...)` before awaiting that work.
- Observable delivery stays synchronous at the core SDK boundary.

## Findings

- #503 is on main. #505 is based directly on main.
- Exact head `8a094caf` passes Source, Clippy, Rust workspace, unit, integration, runtime, packaging, and Maintenance autofix. Product alone fails because the first Lua observable delivery never arrives.
- Client-side and server-side ACP handler spawning are both present. The ACP SDK documents `block_task()` as valid from the `connect_with` foreground future, so the server callback select loop is not the remaining dispatch-loop deadlock.
- Root cause: `SdkApplicationService::invoke` validates `InvokeCapability` against the full outer `Type::Callable`, then passed that same outer schema to `admit_client_callables` while pairing it with the capability input value. For observable `listen`, the pair is `Callable` + input `Table`, so recursion never reaches `listener: Callable`.
- The unadmitted listener then fails capability lookup with `UnknownReference`. Observable delivery intentionally ignores callback errors, so subscription creation still succeeds and the packaged Lua fixture only observes a missing callback.
- The repair admits client callables against the invoked capability's input schema. A new regression covers a client-owned callable nested inside a runtime capability input table.
- Generic capability dispatch validates input before provider code and output before release. Explicit client-tool removal unregisters the lifted callable; disconnect retires the client generation.
- `execute_admitted_client_tool_call` covers permission allow, deny, permission-free dispatch, and ordinary result projection, but its cancellation/disconnect result shape still needs review before completion.
- The active model path uses `ModelToolDescriptor` and `ModelToolCall`; the older handoff wording about a production `ToolProvision` merge point is stale. The agent loop still returns model tool calls without executing them.
- The packaged Lua fixture covers SDK acquisition, observable callback delivery, client-tool registration, invocation, removal, and stale invocation through ACP. It still does not prove the production model-loop join.

- Client-specific backend tool protocol: rejected. Use ordinary model-tool and generic capability contracts.
