## Decisions

- #503 is on main. Reuse its generic CallableRef and dispatcher rather than callback-specific transport.
- Admissions are ephemeral and generation scoped; the backend sees only ordinary CallableDescriptors through ToolProvision.
- One ACP callback queue serves one client connection, so its add/invocation paths accept only that owner and generation.
- Provider adapters translate the backend-neutral model tool surface at the protocol boundary; providers do not gain a client-tool-specific path.
- ToolProvision merges ordinary CallableDescriptors without accepting ClientToolAdmissions. Admission ownership stays above the backend boundary.
- Session admission descriptor projection is deterministic by callable id before it reaches ToolProvision.

## Findings

- This branch is based directly on main after #503.
- Current HEAD 6386fe2c has exact-head CI and Maintenance green; the previous manual-CI handoff is stale.
- Transport closure permanently retires the client owner generation. New service instances start with an empty admission registry, so reconnect cannot revive prior tools.
- A disconnected generic client callable retires its capability references and session admissions. Application session ids are converted to the domain boundary before admission/removal.
- The ACP application service admits client tools and exposes callable discovery/invocation through the generic capability dispatcher; explicit removal disables both.
- Execution uses the public model-routing ABI. The model ABI carries backend-neutral tool descriptors and structured tool calls, and the agent-loop regression proves both survive its routing boundary.
- OpenAI Responses, OpenAI Chat Completions, and Anthropic Messages encode the same backend-neutral descriptor surface and decode structured provider tool calls into ModelToolCall.
- ToolProvision is origin-neutral and rejects duplicate callable ids before backend preparation.
- No production BackendHost implementation currently joins admitted client callables to backend execution. The existing BackendHost implementations are backend tests, so this remains the main execution integration gap.
- phenix-binding-lua already lifts Lua functions into client-owned CallableRefs and sends generic application operations through _invoke_application. tools.register should compose that path rather than add a callback registry.
