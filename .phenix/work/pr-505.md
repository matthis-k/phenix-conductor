## Decisions

- #503 is on main. Reuse its generic `CallableRef` and dispatcher rather than callback-specific transport.
- Admissions are ephemeral and generation scoped; the backend sees only ordinary `CallableDescriptor`s through `ToolProvision`.
- One ACP callback queue serves one client connection, so admission and invocation accept only that owner and generation.
- Provider adapters translate the backend-neutral model tool surface at the protocol boundary; providers do not gain a client-tool-specific path.
- `ToolProvision` stays origin neutral; admission ownership remains above the backend boundary.
- Session admission descriptor projection is deterministic by callable id before backend presentation.

## Findings

- #505 is based directly on main after #503.
- Exact-head CI at 0cbdec0c is blocked before jobs start with GitHub `action_required`; there are no job logs to inspect yet.
- Transport closure permanently retires the client owner generation. A new service starts with an empty admission registry.
- Generic capability dispatch validates callable contract/input before provider code and validates output before release. Cancellation and disconnect remain structural errors.
- ACP application operations already admit, list, invoke, and remove client tools through the generic capability registry.
- The execution/model path carries backend-neutral tool descriptors and typed `ModelToolCall`s, but the agent loop currently returns tool calls without executing them.
- `ToolProvision::merge_callables` is origin neutral and rejects duplicate ids, but no production execution assembly currently joins admitted client descriptors with runtime/plugin descriptors before provisioning.
- `phenix-binding-lua` already lifts Lua functions into client-owned `CallableRef`s and routes fixed application operations through `_invoke_application`; `phenix.tools.register` still needs to compose those mechanisms without another callback registry.
- Added a public integration regression that retires the old client generation, proves the old callable is stale, re-admits the same tool id with a new generation, and invokes the new callable successfully.

## Tried / rejected

- Do not wire client-tool execution through the legacy backend boundary alone: the active execution/model path is the plugin model-routing ABI, and it currently lacks the production admission/invocation join.
