## Decisions

- Observable resources stay ordinary runtime-owned `get` and `listen` callables. The listener is a generic client-owned `CallableRef`.
- The listener input uses the core canonical delivery schema. It preserves commit, value, version, address, subscription, generation, diff, and full-snapshot data.
- A successful observable stop removes its lifted local listener entry. Queued callbacks then fail before Lua dispatch, while a failed stop leaves the listener live.
- Keep runtime-to-client invocation on the same `CapabilityInvokeInput/Result` application callback. Do not add an observable-specific callback path.
- Admit client-owned callable leaves from the authoritative input schema before dispatch; the exact admitted schema remains the registry schema used for input/output validation.
- Preserve callback failures structurally across ACP instead of collapsing them into display-string provider failures.
- Keep `phenix-binding-lua` host-linked validation in packaged LuaJIT checks. Its Rust lib test target is intentionally disabled by #491.

## Findings

- The generic runtime-to-client bridge is implemented: typed client-owned callable leaves are admitted into `SharedCapabilityRegistry`, forwarded over the canonical ACP capability callback, and serviced from blocking runtime dispatch without blocking the Tokio executor.
- The bridge queue is bounded. Queue saturation maps to `CapabilityError::QueueFull`; transport disconnect maps to `CapabilityError::Disconnected` and retires the client owner generation.
- Callback failure propagation is structural on both sides. The client maps host callback cancellation, disconnect, queue-full, and schema failures to structured ACP errors; the server maps those back to `CapabilityError` without terminating the whole stdio connection.
- Exact-head CI and Maintenance for f4e20a27583a3a24ccb4b018d8674f322977a30b are green. The PR body's manual-approval blocker is stale.
- The existing packaged LuaJIT check only proved module loading and descriptor binding. It did not exercise a live SDK or callback path.
- This implementation adds a packaged observable callback regression backed by the production `SdkApplicationService` and ACP stdio server. It retrieves the SDK, invokes `get`, lifts an ordinary Lua listener, forces an initial-full runtime callback, requires Lua host polling before callback execution, inspects lazy delivery userdata, and invokes the returned stop capability.
